The C4 model

Each of the four core levels below now has its own full article — intent, structure, elements, interactions, motivation, audience and common pitfalls, not just a summary. The three supplementary diagrams are filed elsewhere — you reach for a sequence or deployment diagram by the job it does rather than because C4 names it — so their full entries live in those categories; linked below rather than duplicated here. Underneath the four core levels sits a fixed hierarchy: a software system is made up of one or more containers, each of which contains one or more components, which are in turn implemented by one or more code elements — and it is people who use the software systems you build, not the other way round. Simon Brown frames the zoom sequence itself as Shneiderman's mantra — overview first, zoom and filter, details on demand — which is why each level exists to answer a narrower question than the one before it. C4 is a notation, not a methodology: use the levels you need and stop, which for most systems is the first two. Brown's own guidance is blunter still — every software system should have a context and a container diagram; component and code stay optional, worth drawing only where the cost of keeping them current is repaid by the confusion they prevent.
